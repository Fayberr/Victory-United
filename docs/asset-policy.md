# Asset policy (rule #1)

**Nothing from the game is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: data sections, strings, tables,
  resources, code beyond the signatures below;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, screenshots.

## Allowed

* our own code that understands formats;
* build identities: BLAKE3 of an executable, CodeView GUID/age;
* per-build offsets of functions we hook, under names we choose;
* byte-pattern signatures that locate functions or data in the executable;
* small interoperability constants (magic numbers, enum values) we write;
* measurements collected by the project and the GitHub Pages link to those measurements;
* synthetic test data generated by our own code.

## The one exception

`crates/victory-formats/src/bcpack-tables.bin` (about 78 KB): the constant
tables of the BCPack format, which is a Microsoft texture format and not the
title's own (entropy models, index rank tables, control codes, per-format
dictionaries). A BCPack stream has no header and cannot be decoded without
exactly these tables, so they are built into the engine and players need no
extra file. The file was inherited from upstream VIctory, and it was kept by
the project owner's decision (2026-11-23), entered as an exception in
`xtask/src/policy.rs`. It is part of the format, not our work, and the
repository's licence does not cover it. Nothing else of this kind is
accepted.

What is known about it:

* The 128 entropy models (2,304 bytes) are identical to the `freq_table` of
  [`mdu_minirans.v`](https://github.com/microsoft/silicon-rans), which
  Microsoft publishes under the MIT licence. Its notice, kept here as the
  licence requires: "MIT License. Copyright (c) Microsoft Corporation.
  Permission is hereby granted, free of charge, to any person obtaining a
  copy of this software and associated documentation files (the
  "Software"), to deal in the Software without restriction, including
  without limitation the rights to use, copy, modify, merge, publish,
  distribute, sublicense, and/or sell copies of the Software, and to permit
  persons to whom the Software is furnished to do so, subject to the
  following conditions: The above copyright notice and this permission
  notice shall be included in all copies or substantial portions of the
  Software." (The full MIT terms apply, including the disclaimer of
  warranty.)
* The rest (rank tables, control codes, dictionaries) comes from upstream;
  its original source is not recorded.
* If a rights holder objects, the file is removed (see `LEGAL.md` where
  present, or open an issue). A player can still replace it without
  rebuilding: set `VICTORY_BCPACK_TABLES` to the path of a table file of the
  same layout and the engine uses that file instead. A file that does not
  parse is reported and ignored.

The default test suite uses tables generated from synthetic data, plus the
built-in file for one parse check.


## The logo

`branding/` holds the project's own logo, drawn by the project owner, by the owner's decision
(2026-11-27): `vu-banner.png`, `vu-icon.png`, `vu-icon.ico`, `vu-social-preview.png`, `vu-mark-large.png` and
`vu-mark-small.png`. They are our own artwork, used in the README, as the launcher's icon and logo and as
the repository's social image. `xtask/src/policy.rs` allows exactly these six names, each only if it really is a PNG or ICO file and
under 256 KiB. Any other picture anywhere is still refused.

## Run logs

`diagnostics/` holds the layer's own logs of test and play runs, by the
project owner's decision (2026-11-26): every run's log is published there
so that others can read what a run measured. A log is text the layer
wrote; before it is committed it is scrubbed of the user's and the
machine's names and paths, of the title's folder, file, product and
program names, and of the title's own output lines. Nothing of the game is
in it. Because logs are long, `xtask/src/policy.rs` gives the files
directly under `diagnostics/` a rule of their own: a `.txt` up to 32 MiB
that holds no binary data, or a gzipped `.txt.gz` up to 16 MiB. Pictures,
frame shots and anything else a run produces are NOT published: they show
the title.

## Where data lives

Outside the repository, configured in `victory.toml`: `game_dir` (the
user's dump), `test_titles`, and `cache_dir` for everything derived
(default `%LOCALAPPDATA%\victory\cache`).

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist: files must have an allowed
   type, be under 640 KiB, contain no binary data or known binary
   signatures, and hold no long hex/base64 runs or large decimal-byte
   arrays.
3. At runtime, everything that writes derived data calls
   `victory_core::ensure_outside_repo`.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

## If something slips through

A follow-up commit is not enough. Rewrite history
(`git filter-repo --path <file> --invert-paths`), force-push, and have
everyone re-clone.
